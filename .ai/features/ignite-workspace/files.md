# Ignite Workspace Compatibility — File Map

## Owned files

| Path                             | Layer         | Purpose                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ignite.manifest.json`           | Contract      | The template's declaration of its own workspace shape: `workspaceRoot`, two `frontends[]` (path, port, `basePath`, `previewSlug`, `primary`, `devCommand`, `installCommand`, `dependencyManifests`), two `backends[]` (`projectPath`, `assemblyName`, port, `healthPath`, `previewSlug`, `watchGlobs`), `datastores[]`, `validation.frontend` / `validation.backend`, `toolchain`. Strict JSON, no comments |
| `docs/IGNITE-INTEGRATION.md`     | Documentation | The full maintainer guide: topology, ports, mount URLs, the strip/forward rule, HMR mechanics, injected environment, health contract, breakage checklist, local simulation, troubleshooting                                                                                                                                                                                                                 |
| `.ai/features/ignite-workspace/` | Dossier       | This directory                                                                                                                                                                                                                                                                                                                                                                                              |

## Touched files

| Path                                                        | What it contains                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Why it must be touched                                                                                                                                                                                                                                          |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/frontend/main/vite.config.ts`                          | `readEnv`, `basePath`, `configuredAllowedHosts`, `resolveHmrOptions`, `RUNTIME_CONFIG_FROM_ENV`, `collectRuntimeConfig`, `serializeRuntimeConfig`, `hostedPreviewRuntimeConfigPlugin`; `base:`, `server.allowedHosts`, `server.hmr`, `plugins`                                                                                                                                                                                                                                    | The preview proxy forwards the full mount path, so `base` must track `VITE_BASE_PATH`; Vite 403s unknown hosts; HMR needs a pinned client port behind the TLS edge; the app needs its URLs and cookie names at runtime                                          |
| `src/frontend/auth/vite.config.ts`                          | The same block, **duplicated verbatim**                                                                                                                                                                                                                                                                                                                                                                                                                                           | `main` and `auth` are separate Vite projects with separate dependency graphs — a cross-project import would break `vite build`. Only `RUNTIME_CONFIG_FROM_ENV` differs (`VITE_DASHBOARD_URL`→`mainAppUrl` instead of `VITE_AUTH_SERVICE_URL`→`authAppUrl`)      |
| `src/frontend/packages/shared/src/config/constants.ts`      | `AppTemplateRuntimeConfig` optional fields `appBasePath`, `mainApiBaseUrl`, `authApiBaseUrl`, `mainAppUrl`, `authAppUrl`, `sessionCookieName`, `userCookieName` (plus the pre-existing `cookieDomain`); `BACKEND_URL_KEYS`, `FRONTEND_URL_KEYS`; helpers `isAbsoluteUrl`, `normalizeConfiguredBaseUrl`, `joinBaseAndPath`; overrides honoured in `getAppBasePath`, `getBackendBaseUrl`, `getBackendUrl`, `getFrontendUrl`, `getFrontendAssetUrl` and `FRONTEND_CONSTANTS.cookies` | `getAppBasePath()`'s fallback reads only the FIRST path segment, so under `/ignite/coder/@u/w/apps/preview-main/` it answers `"/ignite"` and every derived URL 404s. The overrides let the deployment state the truth instead                                   |
| `src/frontend/packages/shared/src/config/constants.test.ts` | Coverage for every override, absolute-URL overrides, trailing-slash normalisation, cookie-name overrides (via `vi.resetModules()` + re-import, because `FRONTEND_CONSTANTS` is frozen at module evaluation), an exact-fallback test, and two `REGRESSION` tests                                                                                                                                                                                                                   | The REGRESSION tests pin what a deep mount resolves to **without** the overrides (`"/ignite"` and `"/ignite/api-main/api"`) so nobody "fixes" the heuristic by guessing                                                                                         |
| `src/backend/API/Program.cs`                                | `readyTags` on the `AddNpgSql` / `AddRedis` registrations; `MapHealthChecks("/health", …Predicate = _ => false)`, `MapHealthChecks("/health/ready", …Tags.Contains("ready"))`, `MapGet("/health/live", …)`; `using Microsoft.AspNetCore.Diagnostics.HealthChecks;`                                                                                                                                                                                                                | The Coder `main-api` `coder_app` healthcheck polls `/health` every 10 s, 30 failures allowed. A dependency blip would otherwise flip the workspace to _Degraded_ with the API process healthy                                                                   |
| `src/backend/Auth/Program.cs`                               | The identical three-endpoint split                                                                                                                                                                                                                                                                                                                                                                                                                                                | Same probe, plus the cold-boot race: supervisord starts both APIs at the same priority and the database is created by the **Main API's** `Database.Migrate()`, so a Postgres-touching liveness probe reports a perfectly healthy Auth API as dead on first boot |
| `README.md`                                                 | One row in the Documentation table pointing at `docs/IGNITE-INTEGRATION.md`                                                                                                                                                                                                                                                                                                                                                                                                       | Discoverability                                                                                                                                                                                                                                                 |

## Files this feature deliberately does NOT touch

| Path                                                           | Why                                                                                                                                                                                  |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/frontend/main/index.html`, `src/frontend/auth/index.html` | The runtime config is injected by the Vite plugin at serve time; no static markup change is needed                                                                                   |
| `copier.yml`                                                   | No `_exclude` pattern matches `ignite.manifest.json`, so it already ships to every scaffold, and it is deliberately **not** in `_skip_if_exists` so `copier update` keeps it current |
| `build/nginx.conf`, `deploy/`                                  | Production serving is unchanged by this feature — but see the `/health` migration note in `do-dont.md` #8 before releasing                                                           |

## Ignite-side files this feature is a contract with

These live in the **Ignite** repository, not this one. They are the authority on ports, slugs and the injected environment; this template only conforms to them.

| Path                                                              | Defines                                                                                                     |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `build/coder/template/v1/bin/shared.sh`                           | Ports, `IGNITE_DEFAULT_WORKSPACE_ROOT`, the .NET dev-service build/swap loop                                |
| `build/coder/template/v1/bin/run-frontend.sh`                     | Both Vite launches, the nine injected `VITE_*` variables, the dependency watcher, the shared `EXIT` trap    |
| `build/coder/template/v1/bin/run-main-api.sh` / `run-auth-api.sh` | `ASPNETCORE_URLS`, `API.csproj` / `Auth.csproj` paths, assembly names                                       |
| `build/coder/template/v1/bin/inject-vite-origin.py`               | A legacy idempotent Vite patch; a **no-op** against this repo's configs, and must stay that way             |
| `build/coder/template/v1/etc/supervisord.conf`                    | The five programs and their priorities                                                                      |
| `build/coder/template/v1/main.tf`                                 | `coder_app` slugs, healthcheck URLs (10 s interval / 30 threshold), the `IGNITE_*` agent environment        |
| `build/coder/orchestrator/src/server.mjs`                         | `previewAppPorts`, `resolvePreviewProxyTarget()` (the strip/forward asymmetry), the websocket upgrade proxy |
| `build/coder/orchestrator/src/preview-mount.mjs`                  | The mount path regex, app URL composition, the preview ticket cookie                                        |
| `build/nginx.conf`                                                | The four-slug `location` whitelist and the `Upgrade` / `Connection` headers                                 |

## Environment consumed

| Variable                  | Set by                            | Consumed by                                                                                                 |
| ------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `VITE_BASE_PATH`          | `run-frontend.sh`                 | `basePath` → `base`; `appBasePath` in the runtime config; also the trigger for the HMR `clientPort` default |
| `VITE_ALLOWED_HOSTS`      | `run-frontend.sh`                 | `configuredAllowedHosts` → `server.allowedHosts`                                                            |
| `VITE_API_URL`            | `run-frontend.sh`                 | runtime config `mainApiBaseUrl`                                                                             |
| `VITE_AUTH_API_URL`       | `run-frontend.sh`                 | runtime config `authApiBaseUrl`                                                                             |
| `VITE_AUTH_SERVICE_URL`   | `run-frontend.sh` (**main only**) | runtime config `authAppUrl`                                                                                 |
| `VITE_DASHBOARD_URL`      | `run-frontend.sh` (**auth only**) | runtime config `mainAppUrl`                                                                                 |
| `VITE_COOKIE_SESSION_KEY` | `run-frontend.sh`                 | runtime config `sessionCookieName` → `FRONTEND_CONSTANTS.cookies.session`                                   |
| `VITE_COOKIE_USER_KEY`    | `run-frontend.sh`                 | runtime config `userCookieName` → `FRONTEND_CONSTANTS.cookies.user`                                         |
| `VITE_COOKIE_DOMAIN`      | `run-frontend.sh` (empty string)  | runtime config `cookieDomain`; empty values are dropped                                                     |
| `VITE_HMR_CLIENT_PORT`    | **nobody** — our escape hatch     | `resolveHmrOptions()` → `server.hmr.clientPort`                                                             |
| `VITE_HMR_PROTOCOL`       | **nobody** — our escape hatch     | `resolveHmrOptions()` → `server.hmr.protocol`                                                               |
